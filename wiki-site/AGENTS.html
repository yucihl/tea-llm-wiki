AGENTS.md — 茶知識 LLM Wiki

本檔是這個 Wiki 的 Schema（規則書）。任何 agent 在本資料夾工作前都必須先讀完本檔並遵守。 參考：Karpathy〈LLM Wiki〉三層架構（raw / wiki / schema）與三個操作（ingest / query / lint）。

1. 目標

  • 主要目的： 作為知識來源，製作一份給「完全不懂茶的新手」看的教學型 HTML 簡報。
  • 核心範圍： 六大茶類＋台灣特色茶。
  • 輔助範圍（只在支撐核心時寫入）： 茶樹與製茶流程、沖泡基礎、咖啡因、常見迷思。
  • 範圍外（不寫入 Wiki）： 茶道儀式細節、茶具收藏、茶葉價格與購買推薦、醫療功效宣稱。

1.1 簡報區塊規劃

簡報分成數個「區塊」，每個區塊至多 8 頁投影片（不含封面與目錄）。

區塊 主題 主要使用的 Wiki 頁
A 茶是什麼？（茶樹、產地、茶 vs 花草茶） concepts/
B 一片葉子怎麼變成茶（製茶流程、氧化） concepts/
C 六大茶類 teas/、comparisons/
D 台灣特色茶 teas/
E 泡一杯好茶＋常見迷思 concepts/、comparisons/

區塊可以在討論後增刪或調整，但調整時必須同步更新本表，並在 log.md 記錄原因。

3. 命名與格式

3.1 檔名

  • 一律英文小寫＋連字號，例如 oolong-tea.md、oxidation.md、six-tea-types.md。
  • 原始資料檔名：YYYY-MM-DD-來源簡稱-主題.md，例如 2026-11-18-wikipedia-tea.md。
  • 頁面內的標題（H1）一律用繁體中文，例如 # 烏龍茶（青茶）。

3.2 每頁開頭的 frontmatter

---
title: 烏龍茶（青茶）
type: tea            # source | concept | tea | comparison | glossary
sources: [2026-11-18-wikipedia-tea, 2026-11-18-tbrs-taiwan-tea]
updated: 2026-11-18
confidence: high     # high = 兩個以上來源一致 | medium = 單一來源 | low = 有衝突或待查證
slide_block: C       # 這頁主要支撐哪個簡報區塊（可多個）
---

3.3 內文規則

  • 頁面之間用 [[檔名]] 互相連結（不含 .md）。
  • 每個事實句後面標註來源：（來源：[[sources/xxx]]）。
  • 每頁最後有「相關頁面」段落，至少連到 1 個其他頁。
  • 用語以新手看得懂為原則：專有名詞第一次出現時，用一句話解釋。

3.4 raw/ 原始資料的格式

  • 優先存成 Markdown（.md）；PDF 可直接放入；圖片放 raw/assets/。
  • PDF 與圖片無法寫入 metadata，須在旁邊放一個同名的 .meta.md 檔（例如 2026-11-20-tbrs-taiwan-tea.pdf 配 2026-11-20-tbrs-taiwan-tea.meta.md），內容為下方的 metadata 區塊。掃描版 PDF 須先確認文字可選取，否則先做 OCR。
  • 若存檔時刻意略過某些章節，在 metadata 加 excluded: 欄位說明略過了什麼、為什麼。
  • 每個 .md 原始檔開頭必須有以下 metadata（由存檔的人或剪輯工具加上，之後不再修改）：
---
title: 茶 - 維基百科
url: https://zh.wikipedia.org/zh-tw/茶
site: 維基百科
author: 維基百科編者
accessed: 2026-11-18
type: encyclopedia   # encyclopedia | official | article | guide | paper | video-transcript
language: zh-TW
---
  • 存進 raw/ 後內容一律不改；若需要更新版本，另存一個新日期的檔案。
  • 檔案缺 url 或 accessed 時，ingest 前要先在對話中提出，不可直接使用。

4. 工作流程

4.1 Ingest（先討論、後生成）

  1. raw 完整性檢查（不通過就停止，先請使用者補正）： - 檔案有正文，不是空殼、不是摘要或 LLM 改寫的內容 - metadata 齊全（至少 title、url、accessed；PDF 看 .meta.md） - 正文涵蓋的章節與 metadata 或原網頁目錄相符；有缺漏時須有 excluded: 說明
  2. 讀取 raw/ 中新加入的資料。
  3. 先在對話中提出，不可直接寫入： - 3–5 個重點 - 1–2 個疑問（例如與既有 Wiki 矛盾之處、用詞不清、範圍是否要收） - 預計會新增／修改哪些 Wiki 頁
  4. 等使用者確認後才進行以下步驟。← 此關卡不可跳過
  5. 寫 wiki/sources/ 摘要頁。
  6. 更新或新增相關的 concepts / teas / comparisons 頁。
  7. 若出現新名詞，更新 glossary.md。
  8. 更新 index.md。
  9. 執行一次「寫入後檢查」（見 4.4），有問題就修正後再檢查。
  10. 在 log.md 附加紀錄。

4.2 Query（查詢）

  1. 先讀 index.md 找出相關頁面。
  2. 讀取相關頁面後回答，回答中每個重點都要標出來源頁。
  3. Wiki 中沒有的資訊要明說「Wiki 中沒有」，不可用模型記憶補上。
  4. 若回答有保存價值，經使用者同意後存成新的 Wiki 頁。

4.3 產生簡報（Query 的延伸）

  1. 查詢： 依 1.1 區塊表，從 index.md 找出該區塊要用的 Wiki 頁。
  2. 大綱： 寫 output/slides/outline-<區塊代號>.md，每頁投影片列出： - 標題、2–4 個重點、使用的 Wiki 頁、建議圖示或圖表 - 簡報上的每個事實都只能來自大綱列出的 Wiki 頁；Wiki 沒有的內容不可加入
  3. 大綱檢查（見 4.4，用 tools/check_outline.py），不通過就回到步驟 2 重寫。
  4. HTML 草稿： 大綱檢查通過後，可直接產生 HTML 草稿，與大綱一起交給使用者審閱。
  5. HTML 檢查： 實際開啟頁面逐頁截圖，確認可瀏覽、文字沒有溢出、與大綱一致（用 tools/check_html.py）。
  6. 使用者確認： 使用者審閱大綱與草稿後提出修改；修改先改大綱（或 Wiki），再重新產生 HTML，不直接改 HTML 文字。
  7. 定稿前再做一次整體檢查。

修改紀錄：原本規定「使用者確認大綱後才產生 HTML」。2026-11-18 使用者希望先看到簡報畫面，改為大綱與草稿同時審閱；為了不讓確認關卡失效，加上第 2 點的「只能來自 Wiki」與第 6 點的「先改大綱再重生 HTML」。見 log.md。

4.5 Lint（定期健康檢查）

每 ingest 3 篇資料後、以及開始做簡報前，各執行一次： - 頁面之間互相矛盾的說法 - 缺來源的句子 - 孤兒頁（沒有被任何頁連結） - index.md 漏列的頁面 - 名詞與 glossary.md 不一致 - 簡報區塊需要、但 Wiki 還沒有的內容 → 列為「待補資料」

5. 茶主題專屬規則

  1. 名詞以 glossary.md 為準，特別注意： - black tea ＝ 紅茶；dark tea ＝ 黑茶（如普洱）。兩者不可混用。 - 「發酵」在製茶中多半指酵素氧化（黑茶的後發酵除外），第一次出現時必須說明。 - 烏龍茶又稱青茶，兩個名稱都要在 glossary 中對應。
  2. 數字一律附來源：水溫、浸泡時間、茶葉量、咖啡因含量、氧化程度百分比。
  3. 來源互相矛盾時：兩種說法都保留並標記 ⚠️衝突，寫明各自來源，不可自行挑一個；把 confidence 設為 low，並在對話中提出來討論。
  4. 健康相關說法：標記為 🔍待查證，不寫成定論，不放進簡報的主要結論。
  5. 台灣特色茶優先採用台灣官方或學術來源（例如農業部茶及飲料作物改良場）。

6. log.md 格式

每筆紀錄的開頭格式固定，方便日後用 grep 搜尋：

## [YYYY-MM-DD] <操作> | <標題>

<操作> 只能是：ingest、query、lint、slides、fix、schema

每筆紀錄內容包含： - 做了什麼（新增／修改了哪些頁） - 發生的問題（如有）：哪一個節點出錯、錯誤類型、如何修正 - 是否因此修改了 AGENTS.md（若有，另寫一筆 schema 紀錄說明原因）

「發生的問題」與 schema 紀錄是作業步驟四反思的主要依據，出錯時務必記錄，不要只記成功的操作。

7. 修改本檔的規則

  • 只有在使用者同意後才可修改 AGENTS.md。
  • 每次修改都要在 log.md 寫一筆 schema 紀錄：改了什麼、為什麼改、是哪個問題促成的。

8. 簡報視覺規範

8.1 風格

  • 柔和、溫暖、清爽，像一杯淡淡的茶。
  • 以淡綠色系為主色，淺咖啡、淺黃、白、米色為輔色。
  • 避免高飽和色、純黑底、強烈漸層與霓虹效果。

8.2 色彩（CSS 變數，HTML 中一律使用這些變數，不另外寫色碼）

:root {
  /* 主色：淡綠 */
  --green-50:  #F1F6EE;  /* 最淺，可作大面積底色 */
  --green-100: #E4EFDF;  /* 卡片、區塊底色 */
  --green-300: #A8C5A0;  /* 裝飾線、圖示、進度條 */
  --green-700: #4E6B4F;  /* 標題文字（米色底對比 5.5:1） */

  /* 輔色 */
  --cream:     #FAF6EE;  /* 米色：投影片主背景 */
  --white:     #FFFFFF;  /* 白：卡片 */
  --yellow:    #F6EBC4;  /* 淺黃：重點提示框、標記 */
  --tan-200:   #D9C3A5;  /* 淺咖啡：邊框、分隔、裝飾 */
  --tan-700:   #7A5C3E;  /* 咖啡：次要強調文字（米色底對比 5.7:1） */

  /* 文字 */
  --text:      #3F3A33;  /* 內文：暖深灰褐（米色底對比 10.5:1） */
  --text-soft: #6B655C;  /* 註解、來源 */
}
  • 文字只能用 --text、--text-soft、--green-700、--tan-700；--green-300、--tan-200 只用於裝飾，不可當文字色（對比不足）。
  • 六大茶類的代表色可用柔和版本（例如綠茶用 --green-300、紅茶用 --tan-200），但旁邊一定要有文字標籤，不能只靠顏色區分。

8.3 字型與版面

  • 標題："Noto Serif TC", serif；內文："Noto Sans TC", sans-serif。
  • 內文字級不小於 20px（投影片 16:9、1280×720 基準）；每頁重點 2–4 個。
  • 圓角 12–16px、淡陰影（例如 0 2px 8px rgba(63,58,51,0.08)）、留白充足。
  • 每頁頁尾以 --text-soft 小字標註資料來源（對應 Wiki 頁）。
